# A股每日复盘｜ChatGPT 云端任务正式模板

> 目标：每天收盘后生成一份面向交易决策的 A 股复盘，并**真实写入 GitHub**。GitHub commit 是任务成功的唯一判据；不要只在聊天中输出报告后声称完成。

## 1. 固定目标

- 时区：`Asia/Shanghai`
- 仓库：`kakanbai/ai-digest`
- 内容目录：`content/market/YYYY/MM/`
- 当日文件：`content/market/YYYY/MM/YYYY-MM-DD.md`
- 页面固定链接：`/market/YYYY/MM/DD/`
- 布局：`layouts/digest.njk`
- 任务标识：`a-share-daily-review`

仓库已有 GitHub Actions：当 `main` 分支收到提交后，会自动执行 Eleventy/Pagefind 构建、GitHub Pages 发布，并在已配置 `FEISHU_WEBHOOK_URL` Secret 时发送飞书通知。云端任务不要重复实现这些下游步骤，只负责生成高质量 Markdown 并提交到 `main`。

## 2. 执行流程

严格按以下顺序执行：

```text
确定 Asia/Shanghai 当日日期
        ↓
确认当天是否为 A 股交易日
        ↓
检索并交叉验证当天市场数据、公告、政策、新闻、海外变量
        ↓
形成【事实 → 判断 → 推演】
        ↓
生成符合本站 front matter 的 Markdown
        ↓
检查目标文件是否已经存在
        ↓
不存在：GitHub create_file
已存在：fetch_file 获取 SHA → update_file 覆盖为本次完整最新版
        ↓
获得真实 commit SHA
        ↓
GitHub push 自动触发 deploy.yml
        ↓
Eleventy + Pagefind
        ↓
GitHub Pages
        ↓
Feishu（由 Actions 负责）
        ↓
云端任务最终只报告执行状态、文件路径、commit、页面预期路径
```

### 成功判据

只有 GitHub 写入动作返回真实 commit SHA 才能报告：`WRITE_SUCCEEDED`。

以下情况不能报告成功：

- 只生成了 Markdown/HTML，但没有写入 GitHub；
- GitHub 写入失败；
- 因权限问题无法创建/更新文件；
- 把内容只留在 ChatGPT 对话中。

## 3. 数据与研究要求

必须基于当天最新、可靠、可核验的公开信息和市场数据，不要只做新闻罗列或指数播报，而要回答：

1. 今天市场真正交易的核心是什么？
2. 资金从哪里流出，又流向哪里？
3. 哪些方向是真强，哪些只是脉冲？
4. 当前市场处于什么阶段？
5. 下一交易日什么条件下参与，什么条件下回避？

要求：

- 明确区分 `【事实】`、`【判断】`、`【推演】`。
- 重要事实尽量交叉验证。
- 无法核验的数据禁止编造，写 `暂未核验 / 数据缺失`。
- 新闻必须尽量写明发布时间/发生时间与来源。
- 重要数据与新闻在正文中尽量附来源链接；文末增加 `## Sources`。
- 如果当天不是 A 股交易日，不虚构交易数据；生成“休市版”，只记录休市、下一交易日前已知催化、海外变量与风险。

## 4. 必须包含的 18 个模块

### 1）今日一句话结论

用 1-3 句话压缩：指数环境、当前主线、短线情绪阶段、风险偏好。

最终形成类似：

`指数震荡 + AI中周期主升 + 短线情绪分歧`

### 2）大盘与市场广度

至少覆盖：

- 上证指数
- 深证成指
- 创业板指
- 科创50
- 两市成交额
- 较前一交易日增减
- 5日/20日均量对比（可获取时）
- 上涨家数
- 下跌家数
- 涨停家数
- 跌停家数
- 放量上涨 / 缩量上涨 / 放量下跌 / 缩量下跌判断
- 指数强弱与个股赚钱效应是否一致

### 3）市场情绪周期

尽量覆盖：

- 涨停、跌停
- 炸板率
- 最高连板高度
- 首板 / 2板 / 3板 / 4板+
- 昨日涨停今日反馈
- 昨日连板今日反馈

判断短线处于：

`冰点 / 修复 / 回暖 / 主升 / 高潮 / 分歧 / 退潮`

并给出 3-5 条证据。

### 4）市场风格

逐项比较：

- 大盘 vs 小盘
- 价值 vs 成长
- 高股息 vs 科技/题材
- 趋势 vs 连板
- 高位 vs 低位
- 机构 vs 游资

最后给出压缩风格结论。

### 5）板块 / 题材强度排名

选出最重要 3-5 个方向，不按单纯涨幅排名，要综合：

- 持续时间
- 成交额
- 涨停数量
- 核心龙头
- 产业逻辑
- 新闻催化
- 资金容量
- 板块梯队

每个方向必须判断：

- 主线 / 次主线 / 轮动 / 支线 / 一日游
- 当日强度
- 持续性
- 核心催化
- 产业逻辑
- 代表个股
- 是否形成 龙头 + 中军 + 弹性 + 补涨
- 下一交易日验证条件

### 6）资金迁移路径

必须写：

- 主要流入方向
- 主要流出方向
- 高低切 / 大小切 / 价值成长切换 / 新旧主线切换
- 关键迁移链，例如：`传媒 → 半导体 → 煤炭/航运`
- 迁移原因

### 7）核心个股角色表

围绕主线识别：

- 情绪龙头
- 趋势中军
- 高弹性核心
- 低位补涨
- 掉队 / 负反馈

每只写：当天表现、板块角色、对板块影响、下一交易日观察点。

必须额外判断：`超预期 / 低于预期`。

### 8）涨停与梯队结构

分析：

- 主要题材涨停分布
- 首板 / 2板 / 3板 / 高标结构
- 完整梯队 / 单一抱团 / 后排脉冲
- 高度是否打开或出现负反馈

### 9）重要新闻与催化传导链

筛选真正影响 A 股定价的：

- 政策
- 产业新闻
- 公司公告
- 海外市场
- 商品
- 汇率
- 利率
- 科技产业事件

每条重要新闻必须包含：

- 事件
- 发布时间/发生时间
- 事实来源
- 事件性质
- `新闻 → 供需/成本/资本开支/盈利预期 → 行业 → A股受益/承压`
- 代表 A 股公司
- 日内 / 短期 / 中期 / 长期影响
- Price-in 程度
- 最大不确定性

### 10）赚钱效应与交易模式

比较：

- 打板 / 低吸 / 趋势 / 追高 / 埋伏
- 小盘 / 大盘
- 20cm / 10cm
- 高位 / 低位

明确：

- 今日最佳交易模式
- 今日最差交易模式
- 进攻 / 平衡 / 防守

### 11）市场周期判断

同时判断：

- 大周期
- 中周期
- 短周期

说明三周期是否共振或背离。

### 12）今日超预期 / 低于预期

分别列出 3-5 个对象，并解释：

- 为什么超/低于预期
- 对下一交易日的意义

### 13）下一交易日核心观察清单

按高 / 中 / 低优先级列 5-10 个：

- 板块
- 龙头
- 中军
- 商品
- 汇率
- 海外映射
- 政策/事件

每个必须明确“看什么信号”。

### 14）下一交易日三套剧本

至少：

- A. 强势 / 主线加强
- B. 分歧 / 震荡
- C. 弱势 / 退潮

每套包含：

- 触发条件
- 核心股/板块/量能/情绪指标
- 可能演化
- 对应策略

只能做条件式推演，禁止确定性预测。

### 15）股票池 / 观察池

按角色划分：

- 核心
- 低吸观察
- 突破观察
- 补涨观察
- 风险规避

每只必须写：

- 观察理由
- 证伪条件

禁止无条件买卖指令。

### 16）A股与全球市场联动

分析：

- 当日晚间/隔夜美股重要行业与中概股
- 美债收益率
- 美元指数
- 人民币汇率
- 原油、黄金、铜、锂、黑色、有色等与主线相关的商品
- 海外 AI / 半导体 / 新能源 / 医药等核心公司新闻

建立：

`海外变化 → A股行业映射 → 下一交易日验证板块/标的`

若完整隔夜行情尚未发生，必须标记 `待隔夜验证`。

### 17）风险清单

列出 3-5 个最可能导致判断失效的风险 / 证伪条件。

### 18）最终复盘结论

最后再次压缩：

- 今日市场核心
- 当前主线
- 当前情绪阶段
- 当前最佳交易模式
- 下一交易日最关键 3 个验证点
- 一句话风险提示

## 5. GitHub Markdown 模板

生成文件必须以以下 Front Matter 开头，并把变量替换为真实内容：

```yaml
---
layout: layouts/digest.njk
title: "A股每日复盘｜YYYY-MM-DD"
date: YYYY-MM-DD
type: market
task: a-share-daily-review
tags: [A股, 每日复盘, 主线, 情绪周期, 交易计划]
summary: "用一句话概括当天最重要的市场结构。"
generated_by: ChatGPT
permalink: /market/YYYY/MM/DD/
---
```

正文使用标准 Markdown，不要把完整 HTML 存进 `content/market`。

推荐正文标题顺序与第 4 节的 18 个模块保持一致。

## 6. GitHub 写入规则

目标：`kakanbai/ai-digest`

目标路径：

`content/market/YYYY/MM/YYYY-MM-DD.md`

执行前必须检查目标文件：

- 不存在：创建新文件。
- 已存在：先获取当前 blob SHA，再更新为本次完整最新版。允许同一天人工重跑覆盖当天报告。
- 禁止修改与本次复盘无关的文件。

Commit message：

- 新建：`market: add YYYY-MM-DD A-share daily review`
- 更新：`market: refresh YYYY-MM-DD A-share daily review`

## 7. 最终任务回执

GitHub 写入完成后，聊天中不要再次输出整篇报告，只输出简短回执：

```text
WRITE_SUCCEEDED
Date: YYYY-MM-DD
Path: content/market/YYYY/MM/YYYY-MM-DD.md
Commit: <commit-sha>
Page: /market/YYYY/MM/DD/
Pipeline: GitHub push → Eleventy/Pagefind → GitHub Pages → Feishu
```

若失败，则输出：

```text
WRITE_FAILED
Date: YYYY-MM-DD
Path: ...
Reason: ...
```

只有拿到真实 commit SHA 才允许输出 `WRITE_SUCCEEDED`。
